# MouT.me 视觉方案 1

> 归档日期：2026-09-05
> 状态：已确认的概念基线，后续探索不得覆盖本目录

## 这版方案的核心

`MouT.me` 使用一个固定的体素/2.5D 角色作为视觉锚点。角色坐在同一个位置和姿势，页面每次只呈现一个场景，通过状态导航切换创作、游戏、工作和出发等不同环境。

3D 场景负责让人产生兴趣、切换状态和发现入口；文章、音频、产品详情和可试玩项目使用真实的 HTML、音频和独立 URL 呈现。

## 已确认的视觉决定

- 品牌始终写作 `MouT.me`；
- 角色保留黑色几何头发、眼镜轮廓、黑色上衣、体素比例和胸前的“永结童心”标记；
- 角色的位置、坐姿和主要镜头在不同场景之间保持不变；
- 场景拥有各自的主环境色，黄色只作为品牌和角色识别色，不铺满所有场景；
- 创作场景使用通用报纸、CrossPod 麦克风/波形、独立产品原型发射台、三阶魔方和两只猫；
- 游戏场景使用 GBA、童年游戏机/电视、游戏收藏入口，并暂时为未来内容保留扩展位；
- 工作场景以 AI / AI Agent 空间助手为主要焦点，社交、游戏、品牌营销/游戏化互动和电子政务作为次级行业来源；
- 出发场景使用固定车内和单一目的地车窗换景，目的地可以通过车内路书切换；
- 烧酒（狸花猫）和小八（英短蓝白）作为跨场景的生活角色出现；
- 页面不是传统 Hero + 图文排列，不要求访客在开放世界中自由行走，也不以项目复盘和商业指标作为首页主线。

## 需要记住的限制

- 这些图片由 sub2api GPT Image 2 生成，服务实际返回的尺寸低于请求的 4K 尺寸；它们只用于方向、材质和物件语义讨论。
- 图像生成不能可靠保证不同场景中的角色姿态完全一致；正式实现时角色必须是独立的可复用 3D/2.5D 资产，环境单独替换。
- 图片中的文字、界面、行业模块和细节不能直接当作最终 UI；最终内容必须由代码、真实素材和结构化内容数据提供。
- 方案 1 的画面语言仍偏“明亮体素化舞台”，后续允许探索更精致的模型、灯光、材质和渲染管线，但不得改变固定角色、单场景状态切换和内容入口的核心概念。
