# MouT.me 视觉升级调研

> 调研日期：2026-09-05
> 适用版本：视觉方案 1 之后的视觉探索
> 目标：在不改变“固定 MouT 角色 + 单场景状态切换 + 物件内容入口”的前提下，提升模型、材质、灯光、渲染和转场质量。

## 1. 结论先行

当前概念图的主要问题不是概念不成立，而是生产方式决定了画面上限：GPT Image 2 能帮助确定构图、色彩和气质，但不能为最终网站提供稳定的角色模型、可交互物件、跨场景一致姿态或可控的实时灯光。

真正的升级路径应是：

> **人工/程序制作可复用的 3D 资产 + 明确的非写实渲染管线 + 少量定制 Shader + 固定镜头的场景编排。**

不建议把项目升级成写实开放世界，也不建议使用大量粒子、Bloom、霓虹或 Gaussian Splat 作为主要视觉。它们会增加成本，却不一定更像 MouT.me。

## 2. 当前方案保持不变的核心

- 品牌始终使用 `MouT.me`；
- 角色保留体素/2.5D 形象、黑发、眼镜轮廓、黑色上衣和“永结童心”标记；
- 角色位置、比例、坐姿和主摄像机固定；
- 每次只呈现一个场景；
- 通过状态导航切换创作、游戏、工作和出发；
- 物件是内容集合入口，而不是随机装饰；
- 文章、音频、项目和游戏内容使用真实 HTML、音频和独立 URL；
- 黄色是品牌识别色，不是所有场景的背景色；
- 烧酒和小八作为跨场景的生活角色出现。

## 3. 相似项目与可借鉴点

### 3.1 Joseph Santamaria / Sacred Labs

[3D Portfolio: A Scroll-Driven WebGL Environment](https://www.webgpu.com/showcase/joseph-santamaria-3d-webgl-portfolio/)

它使用 Three.js、GSAP、React Three Fiber 和手工编排的场景，把作品集做成一段由滚动控制的空间影像。值得借鉴的不是“滚动进入 3D 世界”，而是：

- 场景由设计者手工布置，而非市场模型拼装；
- 每一段转场都有明确的镜头和节奏；
- 性能预算从视觉概念阶段就参与设计；
- 空间文字和场景构图共同承担叙事。

对 MouT.me 的启发：场景切换要像剪辑和舞台换景，不应只是淡入淡出。

### 3.2 Artisans d'Idées / Immersive Garden

WebGL 社区的案例介绍把这个作品描述为“把阴影当作材质”，通过点击、横向移动和声音状态推进场景，而不是靠大量 UI。参考：[Artisans d'Idées 案例](https://www.webgpu.com/showcase/artisans-didees-threejs-shadow/)。

对 MouT.me 的启发：可以把场景中的阴影、反射、声音和物件响应当作内容的一部分。创作场景里的波形、魔方和猫都应该有微小但真实的响应，不需要堆很多效果。

### 3.3 Ronin161 Portfolio / Codrops

[Case Study: Ronin161's Portfolio 2024](https://tympanus.net/codrops/2024/02/20/case-study-ronin161s-portfolio-2024/)

这个案例没有直接接受 Three.js 默认 Toon Material，而是制作了自己的非写实 Shader：

- 将明暗压缩成少数色阶；
- 用自定义轮廓增强形体；
- 使用噪声破坏过于线性的渐变；
- 根据角色、场景和品牌调整阴影色。

对 MouT.me 的启发：体素角色不应只使用默认 `MeshToonMaterial`。定制明暗阶、阴影色、轮廓和轻微颗粒，才会形成自己的渲染签名。

### 3.4 The Silence Museum / Undream Studio

[The Silence Museum](https://www.undreamstudio.com/projects/the-silence-museum/)

这个项目把 Blender 高质量场景、Three.js/WebGL、相机动画、几何转场和编辑式排版结合在一起，重点是材料、光线和节奏，而不是让访客在复杂空间中寻找东西。

对 MouT.me 的启发：可以借鉴“展览入口、聚焦、返回”的节奏，把每个场景当成一个小型展厅；不需要让用户自由走动。

### 3.5 PlayCanvas / WebGPU / Gaussian Splat

[PlayCanvas 官方平台](https://playcanvas.com/)目前同时支持 WebGL、WebGPU、计算 Shader 和 Gaussian Splat，并强调流式加载与跨设备运行。

Gaussian Splat 很适合把真实旅行地点做成漂亮的远景或车窗外背景，但它不适合作为 MouT.me 的核心交互资产：它更接近“从多个视角重建外观”，不天然提供可点击的物件、稳定的语义节点和可复用的角色层。这是基于技术形态的判断，不是对具体项目效果的否定。

对 MouT.me 的启发：目的地远景可以以后试用 Splat 或烘焙渲染，角色、猫、GBA、魔方、麦克风和 Agent 工具必须保持为可控的 GLB/几何资产。

### 3.6 真实项目的工程共性

一个开源的 React Three Fiber 3D Portfolio 记录了常见组合：React、Vite、Three.js、R3F、Drei、GSAP、后处理、角色场景和自定义光标。[项目 README](https://github.com/akashrmalhotra/3d-portfolio)

它的价值不在于直接复用视觉，而在于说明工程拆分方式是可行的：角色、场景、动画、内容数据和工具函数应有明确边界。

### 3.7 Three.js Journey 的位置

[Three.js Journey](https://threejs-journey.com/) 目前已经覆盖 Blender、烘焙场景、灯光、阴影、环境贴图、真实渲染、模型导入、鼠标事件、性能优化，以及新的 WebGPU/TSL 课程。它仍然是很好的技术基础，但不应直接被当作 MouT.me 的美术方向。

它最值得继承的是制作流程：先在 Blender 中完成资产和灯光，再导出到浏览器，最后用 Three.js 处理交互和状态；它的基础渲染范式则需要被更明确的个人视觉系统替代。

## 4. 建模与渲染风格比较

### 4.1 软光 C4D / 产品展示风格

特征：大面积柔光、干净背景、柔和阴影、圆润边缘、轻微反射和很少的纹理。

优点：第一眼高级、容易读、适合展示道具和产品。

缺点：很容易变成通用的 3D 产品图；如果所有场景都使用这种方式，MouT.me 的个人记忆会被“漂亮的物件”稀释。

适合 MouT.me 的部分：独立产品原型仓、AI Agent 核心、GBA 和魔方等需要像产品展示的物件。

不适合作为全站唯一风格。

### 4.2 Toon / Cel 风格

特征：少量明暗色阶、明确轮廓、可控的阴影色、轻微抖动或颗粒。

优点：角色和道具的识别度高，画面不会依赖大量真实纹理；可以让体素角色摆脱“粗糙方块”的感觉。

缺点：默认 Toon Material 仍然很容易显得像教程示例；轮廓过重会让场景变成卡通游戏。

适合 MouT.me 的部分：固定角色、猫、游戏场景和场景转场中的角色保持。

实现参考：[Three.js Toon Material 示例](https://threejs.org/examples/webgpu_materials_toon.html) 与 [Ronin161 的自定义 Toon Shader 拆解](https://tympanus.net/codrops/2024/02/20/case-study-ronin161s-portfolio-2024/)。

### 4.3 手绘 / 纹理化低模

特征：模型保持低多边形，但通过手绘贴图、烘焙 AO、局部粗糙度和不规则边缘增加细节；阴影和材质不追求完全物理正确。

优点：个性强、耐看，适合纸张、旅行场景、游戏道具和有记忆感的物件。

缺点：资产制作比“纯色方块”更慢；贴图需要统一风格，否则会出现每个物件像来自不同项目的问题。

适合 MouT.me 的部分：报纸、旅行物件、GBA、车内材质、猫和旧网站魔方。

### 4.4 平面舞台 / 2.5D Cutout

特征：正交或轻透视镜头、清晰的平面色块、有限深度、强构图、局部 3D 厚度和可控的投影阴影。

优点：非常适合固定角色和单场景切换；渲染稳定、移动端成本低，画面可以比纯低模更有设计感。

缺点：如果所有场景都做得过于平面，会显得像插画或舞台模型，缺少空间层次。

适合 MouT.me 的部分：作为全站骨架。角色和主要道具保持 2.5D 设计，少数核心物件再使用真正的 3D 细节。

### 4.5 影视级 PBR / 写实风格

特征：连续真实光照、复杂反射、真实材质、景深、体积光和高分辨率纹理。

优点：视觉冲击力强，适合电影、旅行和产品广告。

缺点：建模、灯光、纹理、加载和设备要求都高；写实风格与体素角色放在一起容易失去统一性。

适合 MouT.me 的部分：不作为全站基础。可以把某些旅行远景或电影片段做成高质量背景，但角色和交互物件仍保持风格化。

## 5. MouT.me 推荐的混合风格

暂定名称：**Graphic Voxel Scene / 图形化体素舞台**。

它不是单纯的 C4D、Toon、低模或像素风，而是由以下规则组成：

### 5.1 几何

- 角色保留体素化轮廓和有限面数；
- 家具、设备和车辆使用干净的硬表面模型；
- 重要边缘使用小倒角，让光线能在边缘停留；
- 报纸、票据、波形和路线使用曲面或程序化曲线；
- 猫使用较柔和的低面数体块和真实花色；
- 不让所有物件都由相同尺寸的方块拼成。

### 5.2 明暗

- 角色使用 2–3 段明暗色阶；
- 主要物件使用稍微连续的明暗，保持材质差异；
- 阴影颜色随场景变化，但不使用纯黑压死细节；
- 轮廓只用于角色、猫和主要可交互物件；
- 用轻微噪声破坏过于完美的色阶边界。

### 5.3 灯光

- 一盏大面积主光定义场景方向；
- 一盏低强度填充光保留暗部；
- 一点轮廓光将角色从背景中分离；
- 使用接触阴影表现坐姿、桌面、猫和物件之间的关系；
- 交互状态通过局部亮度、色彩或阴影变化提示，不依赖 Bloom。

### 5.4 材质

- 角色服装：哑光、高粗糙度、少反射；
- 黑色工作台和设备：粗糙黑色，边缘有克制高光；
- 报纸、票据和稿纸：细微纤维、弯曲和厚度；
- GBA、电视和魔方：有限半光泽，突出形体；
- Agent 指令环和波形：干净的半发光材质，亮度受控；
- 旅行远景：可以比室内物件更接近 PBR，但保留统一色彩等级。

### 5.5 镜头

- 主镜头固定，角色位置始终稳定；
- 场景采用轻微正交/45 度视角，让空间关系容易理解；
- 不使用大幅镜头飞行来制造“高级感”；
- 物件靠近或展开时只进行局部尺度、旋转和深度变化；
- 每个状态使用不同的环境色和光线方向，但不改变角色构图。

## 6. 技术落地建议

### 6.1 第一阶段：稳定 WebGL 基线

- Blender 制作角色和第一批物件；
- 导出 GLB，使用 React Three Fiber 加载；
- 使用 WebGLRenderer 验证固定相机、灯光、阴影、热点和转场；
- 使用自定义 GLSL 或材质节点做第一版 Toon/阴影实验；
- 先把创作场景做到可用，不追求一次加入所有高级效果。

### 6.2 第二阶段：迁移高价值 Shader

- 将 AI Agent 指令环、CrossPod 波形、魔方旋转和场景换景效果单独迁移到 WebGPU/TSL；
- 使用 `WebGPURenderer`，保留 WebGL 2 回退；
- 避免把所有材质都改成复杂节点，优先迁移确实能形成个人辨识度的效果；
- 通过 Render Target、纹理反馈或 TSL 实现局部变形，而不是在整屏使用重后处理。

### 6.3 第三阶段：目的地和高级背景

- 旅行场景先使用轻量 GLB 或烘焙背景；
- 如果某个地点值得更真实的空间感，再尝试 Gaussian Splat；
- Splat 只负责远景和窗外氛围，角色、车内、路书和热点仍由普通模型与 DOM/Canvas 控制；
- 每个目的地只加载一个外部环境，切换时释放旧资源。

## 7. 视觉升级的实际优先级

1. 角色模型和固定姿态；
2. 创作场景的建模比例、材质和灯光；
3. 工作场景 AI 核心的材质和空间交互；
4. 自定义 Toon/阴影/轮廓签名；
5. 创作 → 工作的物件转场；
6. 猫、魔方、波形的微动画；
7. 游戏和出发场景；
8. WebGPU 特殊效果和 Gaussian Splat 实验。

如果前两项没有做好，增加 Shader、粒子和后处理只会让粗糙的模型动得更复杂。

## 8. 性能与加载

React Three Fiber 的性能指南建议在场景静止时使用按需渲染、缓存 GLTF、使用 LOD 和 PerformanceMonitor。[Scaling Performance](https://r3f.docs.pmnd.rs/advanced/scaling-performance) 和 [Loading Models](https://r3f.docs.pmnd.rs/tutorials/loading-models) 可作为实现参考。

应用到 MouT.me：

- 当前场景保持动态时正常渲染；静止后使用按需渲染；
- 当前状态和下一个可能状态优先加载；
- 猫、波形和魔方使用轻量独立动画；
- 远处背景使用低细节模型或烘焙层；
- 只有当前热点进入近景时才加载高分辨率内容；
- 监听 FPS，降低 DPR、阴影、纹理和后处理；
- 文章和项目页面不依赖 3D 资源加载完成。

## 9. 视觉升级优先级

| 优先级 | 升级项 | 预期收益 | 成本 |
|---|---|---|---|
| P0 | 固定角色独立模型与统一姿态 | 解决跨场景连续性 | 中 |
| P0 | 创作场景真实资产重做 | 解决“物件随意、含义不强” | 中 |
| P0 | 统一灯光、阴影和色彩管理 | 解决生成图与实时渲染差异 | 中 |
| P1 | 自定义 Toon/TSL 材质与轮廓 | 建立 MouT.me 的渲染签名 | 中高 |
| P1 | 创作 → 工作转场 | 验证核心交互 | 中高 |
| P1 | 两只猫、魔方、波形的微动画 | 增加生命感和可玩性 | 中 |
| P2 | 出发场景目的地背景 | 丰富旅行状态 | 中高 |
| P2 | WebGPU 特殊效果 | 提升高级感 | 高 |
| P3 | Gaussian Splat 目的地实验 | 增加真实空间感 | 高，且只适合局部 |

## 10. 推荐实施顺序

### Slice 1：创作场景

先只做一个完整场景：

- 固定 MouT 角色；
- 通用报纸；
- CrossPod 麦克风/波形；
- 独立产品原型发射台；
- 三阶魔方；
- 烧酒和小八；
- 三个可点击热点；
- 文章、音频、独立产品预览层。

### Slice 2：创作 → 工作

- 角色和摄像机保持不动；
- 报纸折叠为原型模块；
- 波形变为 AI 指令环；
- 工作场景只加载 AI / Agent 核心和少量行业来源模块；
- 验证 60fps、重复点击、返回和减少动画。

### Slice 3：AI Agent 交互

- 鼠标靠近或语音触发指令环；
- 工具模块按需出现；
- 点击核心模块打开 Super Intern、Dimensional Inn 或其他 AI 产品集合；
- 对话层使用真实 HTML，不把聊天内容烘焙进纹理。

### Slice 4：游戏和出发

- 加入 GBA 可试玩入口；
- 加入车内固定场景；
- 先做一个巴统目的地；
- 再扩展新疆和日本城市；
- 每个目的地只替换车窗外单一环境。

## 11. 判断升级是否成功

视觉升级成功的标准不是“模型更写实”或“粒子更多”，而是：

- 不看文字也能认出固定角色是 MouT.me；
- 同一角色在所有场景中姿态和比例一致；
- 每个主要物件都对应真实经历；
- 场景色彩各自成立，同时保留品牌连续性；
- 材质、阴影和轮廓形成稳定的个人渲染风格；
- 场景切换像有意义的换景，而不是页面刷新；
- 3D 交互让人更愿意了解你，而不是增加学习成本；
- 文章、音频、项目和游戏仍然易读、易听、易访问；
- 移动端和低性能设备不会被迫承担桌面级特效。
