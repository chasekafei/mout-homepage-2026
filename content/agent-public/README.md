# Agent public corpus

这里是个人 Agent 允许引用的公开资料。文件以小段落为单位维护；每段应包含明确事实或已经公开表达过的观点。

建议在发布前把原始简历、客户名称、内部项目细节和私人联系方式重新审核一遍。`visibility: private` 的资料不应进入公开构建产物。

第一阶段可以直接把 Markdown 转换成 `PersonalFact[]`，不需要向量数据库。后续如果资料规模变大，再增加向量检索或全文索引。

## 添加一条资料

每条资料只讲一个主题。`title` 写标准主题，`body` 写可引用的事实或观点，`tags` 写 3-8 个短概念，`keywords` 写项目名、产品类别、常见同义词，`queries` 写 2-5 个访客可能直接使用的问法。

```json
{
  "id": "project-example",
  "title": "项目标准名称",
  "body": "谁在什么背景下做了什么，以及结果或本人判断。",
  "tags": ["项目类型", "行业", "角色"],
  "keywords": ["项目别名", "常见产品叫法", "核心能力"],
  "queries": ["这个项目是什么", "你在项目里负责什么", "当时为什么这样设计"],
  "source": "docs/公开来源.md#项目段落",
  "visibility": "public"
}
```

检索会对中文做字符 n-gram 匹配，并对标题、关键词、标签和正文分别加权。`queries` 是最高信号的自然问法匹配。普通问答优先从最近用户问题和近两轮上下文共同检索；新加或改写资料后运行 `pnpm test:retrieval` 检查覆盖情况。

评测样例位于 `packages/agent-core/test/retrieval.test.ts`。加入新主题时，应同时补一两条代表性问法及预期 fact ID，避免资料存在但用户常用说法召回不到。
